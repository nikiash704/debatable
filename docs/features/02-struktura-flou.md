# Фича 02: Структура флоу (главная фича)

**Статус:** решено. **Этап 1 утверждён к кодингу** (спецификация — раздел «Этап 1» ниже). Этапы 2–3 — согласованный план.
**Обновлено:** 10.11.2026
**Связано:** 01 (синхронизация через CRDT/Yjs, комната = одна команда в v1)

## Суть
Как аргументы пишутся, выглядят, делятся на подтезисы, переходят между колонками, считаются, двигаются,
как работают стрелки. Обсуждали от лица оппозиции; для правительства всё зеркально.
Источник примеров: раунд «Ocean vs Space» (мы — оппозиция): Google-док брейншторма + Excel-флоу.

## Этап 1 — спецификация для кодинга (утверждено 10.11.2026)

### Входит
Конфиг формата + стадии (п.6), карточки и тезисы (п.2), нумерация (п.2.2), создание карточки в любом месте (п.4),
«сказано» + режим речи + счётчик + перенос к MO + красное в LOR (п.7), «сильный» и теги (п.5, 5.2), хоткеи.
Обе стороны (оппозиция и правительство) — через конфиг, без отдельного кода.

### Не входит (этап 2–3)
Стрелки и выравнивание рядов, фокус/затемнение, счётчик «на что ответили» (п.8, 9), зелёная подсветка
сказанного и стрелки в LOR (п.11), вид-документ для подготовки и автопереход после 15 минут (п.1),
перетаскивание (п.3), группировка чужих (п.10), «dropped by Gov» (п.12).
Но **модель данных этапа 1 уже содержит поля для них** (`respondsTo`, `groupId`), чтобы не переделывать.

### Модель данных
- **Карточка:** `id` (внутренний, никогда не меняется), `side` (gov/opp), `ownerSpeech` (речь-колонка,
  например LOC / MO / PMC для чужих), `zone` (`clash` — ответы сверху колонки, `own` — свои аргументы снизу),
  `series` (A / C / R для своих; для чужих — по речи), `displayNumber`, `numberLocked`, `thesisId`
  (только для своих аргументов), `text`, `points[]` (пункты), `strong`, `tags[]`, `saidIn` (речь или null),
  `carriedFrom` (речь, откуда перенесена, или null), `respondsTo[]` (этап 2), `groupId` (этап 3), `order`.
- **Тезис:** `id`, `side`, `title`, `order`. Номер тезиса — по порядку.
- **Тег:** `type` (no-warrant / nonsense / same-as / contradicts / turn / poo), `refCardId` для same-as и contradicts.
  Ссылка хранит внутренний `id`, на экране показывается текущий номер.
- **Стадия** — общее состояние комнаты (синхронизируется). Порядок берётся из конфига:
  APDA = Prep → PMC → LOC → MG → MO → LOR → PMR → Разбор.

### Конфиг формата (под будущий BP)
Всё, что зависит от формата, — в конфиге; движок стадий, правила зачёркивания/переноса/красного,
нумерация и счётчики читают только его. Минимум полей:
- `prepMinutes` (по умолчанию 15, можно 0);
- `sides[]`: id, префикс (APDA: `O` и `G`), члены команды (LO, MO / PM, MG);
- `speeches[]` по порядку: id, подпись колонки, сторона, спикер, минуты, `allowsNew` (false для LOR/PMR),
  `prefixSeries` (A/C для конструктивных, R для ребатлов), `carriesTo` (куда уходит несказанное: LOC → MO,
  PMC → MG), `liveFrom` (с какой стадии номера колонки живые: LO — с Prep, MO — с MG, PM — с Prep, MG — с LOC),
  `defaultTargets` (на какие речи отвечает по умолчанию — для этапа 2).
Проверка: тестовый конфиг с другим набором речей меняет стадии и колонки без правок движка.

### Колонки и вид
- Колонка на каждую речь: PM | LO | MG | MO | LOR | PMR (у оппозиции LOR — своя колонка, у правительства PMR).
- Внутри своей колонки: сверху зона ответов (OC), снизу свои аргументы, сгруппированные по тезисам
  (тонкая линия слева + заголовок тезиса «1 · …»).
- Чужие речи (PM, MG, PMR для оппозиции) — простой список карточек PM1, PM2… / MG1… / PMR1…
- Карточка: номер, звезда если сильная, текст, пункты свёрнуты до первой строки + «•3», раскрытие по клику,
  теги — маленькие плашки.
- Панель стадий сверху: все стадии, текущая выделена, кнопки «назад/дальше». Переход вручную
  (таймер и автопереход — отдельно, позже).

### Нумерация (решение пользователя)
- Свои серии: OA (аргументы), OC (контраргументы), OR (LOR); у правительства GA / GC / GR (PMR).
- Номера колонки живые (подряд по позиции, пересчитываются при вставке/удалении/перестановке) от `liveFrom`
  до конца речи владельца. LO: Prep → PMC → LOC, блок при LOC → MG. MO: MG → MO, блок при MO → LOR.
  LOR: живые во время LOR. Ответы LO, написанные во время PMC, на переходе PMC → LOC не блокируются.
- Чужие колонки живые во время своей речи, блок при переходе к следующей.
- Серии продолжаются: первый OC у MO = последний OC у LO + 1; новые OA у MO = последний OA + 1.
  Перенесённые от LO карточки сохраняют свои заблокированные номера.

### Поведение по стадиям (оппозиция; правительство зеркально по конфигу)
- **Prep:** создаём тезисы, OA-карточки и пункты прямо на доске.
- **PMC:** пишем PM1… в колонку PM; LO пишет OC в свою зону ответов.
- **LOC (речь LO):** у LO включён режим речи. Клик по карточке = «сказано» (зачёркнута), повторный — снять.
  Счётчик над колонкой: «сказано X / Y».
- **LOC → MG:** номера LO блокируются. Все несказанные карточки LO (OA и OC) переезжают в колонку MO,
  сохраняя номер и тезис, с плашкой «from LO».
- **MG:** пишем MG1… в колонку MG; MO готовит ответы (OC продолжают серию).
- **MO (речь MO):** режим речи у MO; зачёркивание и счётчик для колонки MO (включая перенесённые).
- **MO → LOR:** номера MO блокируются. Зачёркивания на всей доске визуально снимаются (данные `saidIn` остаются).
  Все свои карточки, которые не были сказаны ни в LOC, ни в MO, — красные с плашкой «new — don't say».
  В LOR создаются OR-карточки. Тег POO доступен только в ребатлах (`allowsNew = false`).
- **PMR:** флоуим PMR1… Красного у оппозиции в PMR нет.
- Зеркало для правительства: PM — свои GA (контраргументов нет), несказанное PM уходит к MG; MG отвечает на LO,
  потом свои новые; PMR = GR. Красное в PMR — только для старых несказанных карточек; новые ответы на
  новые аргументы MO создаются как новые GR-карточки, поэтому исключению правила PMR это не мешает.

### Режим речи
- Включается автоматически на устройстве текущего спикера. **Решение по умолчанию для кодинга:**
  при входе в комнату устройство выбирает роль (LO / MO или PM / MG), выбор запоминается на устройстве;
  напарник может включить/выключить режим речи вручную.
- В режиме речи: карточки — крупные цели, клик/тап = «сказано», текст правится только двойным кликом.
  Клавиатура: ↑/↓ — выбор карточки, Space — «сказано», после этого выделение переходит к следующей.

### Создание и ввод (всё доступно и мышью, и клавиатурой)
- Мышь: плюсик в любом промежутке колонки (в начале, между карточками, в конце); по умолчанию новая —
  под последней. При наведении на карточку — мини-панель: звезда, теги, «сказано».
- Enter — новая карточка ниже; Tab / Shift+Tab — уровень (пункт ↔ карточка ↔ тезис); Esc — выйти из редактирования.
- Cmd/Ctrl+Enter — «сказано» (вне режима речи).
- Карточка выделена, но не редактируется: S — сильный, W — no warrant, N — nonsense, T — turn,
  = — same as…, C — contradicts…, P — POO (только в ребатлах). Same as / contradicts открывают выбор карточки.
- Cmd/Ctrl+K — палитра команд с подписанными хоткеями. У каждой кнопки подсказка с хоткеем при наведении.

### Критерии готовности (проверять на раунде Ocean vs Space)
1. Prep: 3 тезиса, 6 карточек OA1–OA6 с пунктами; вставка карточки в середину перенумеровывает подряд.
2. PMC: PM1–PM5 в колонке PM; OC1–OC4 у LO; номера живые и в LOC.
3. LOC: клик по карточке зачёркивает, счётчик «сказано 7/10».
4. Переход к MG: номера LO заблокированы; несказанные OA2, OA4, OA6 переехали к MO с плашкой «from LO».
5. MO: новый ответ получает OC5, новый свой аргумент — OA7; зачёркивание и счётчик работают.
6. LOR: зачёркивания сняты, несказанное красное, POO доступен, OR1, OR2 пересчитываются при вставке.
7. Тот же сценарий за правительство даёт GA / GC / GR.
8. Каждое действие выполнимо и мышью, и хоткеем; подсказки хоткеев видны.
9. Два устройства в одной комнате видят стадию, карточки и зачёркивания синхронно (фича 01).
10. Тестовый конфиг другого формата меняет стадии и колонки без правок движка.

## Этапы 2 и 3 (согласованный план)
- **Этап 2 (столкновение):** строки-нити — ответ встаёт в ряд с тем, на что отвечает, стрелка рисуется
  автоматически по `respondsTo`; ответ на два аргумента (п.9); фокус — цель подсвечена, остальные колонки
  затемнены, только у пишущего; счётчик «на что ответили» (в MO: «MG отвечено x/y · от PM осталось z»);
  в LOR — зелёная подсветка сказанного и стрелки (п.11); вид-документ для подготовки = та же модель данных,
  переключение вида после таймера (п.1); перетаскивание с «расступанием» (п.3).
  Порядок ответов MO: сначала MG, потом оставшееся от PM (ответ встаёт в ряд неотвеченного PM, стрелка
  идёт напрямую), потом свои аргументы.
- **Этап 3:** группировка чужих аргументов тем же механизмом, что тезисы (п.10); «dropped by Gov» —
  свой сказанный аргумент без входящей стрелки от соперника, подсказка для LOR (п.12).

## Требования пользователя (раунд 1, как сформулированы)
1. Подготовка 15 минут: простой редактор как Google Doc, три уровня: цифры (тезисы), буквы (аргументы), пункты.
   По окончании времени автоматически переносится на доску.
2. Буква → карточка-аргумент; карточки сгруппированы под тезисом линией слева; пункты внутри карточки.
2.2. Нумерация: OA# пока не начались контраргументы, потом OC#; в LOR — OR#.
3. Перетаскивание карточек; остальные расступаются, показывая место приземления.
4. Создание карточки в любом месте: по умолчанию под последней, плюсик в любом промежутке.
5. Пометка «исключительно сильный» — для своих и чужих аргументов.
5.2. Быстрые ответы на чужие аргументы.
6. Переключение стадий во всём приложении; от стадии зависит поведение карточек.
7. Зачёркивание сказанного, счётчик, перенос несказанного к MO, в LOR несказанное красным.
8. Стрелки 1-к-1, фокус на цели, счётчик ответов.
9. Одна карточка отвечает на две чужие.
10. Группировка чужих аргументов.
11. В LOR подсветка сказанного и стрелки.
12. Отслеживание, что оппоненты законтрили.

## Решения пользователя (раунды 2–4)
- Нумерация, префиксы GA/GC/GR, теги, ввод «мышь + продуманные хоткеи», спикер зачёркивает сам,
  порядок ответов MO, конфиг под BP — см. спецификацию выше.
- Раунд 4: все предложения Claude (две вида одной модели, строки-нити, режим речи, хоткеи, порядок этапов)
  приняты; этап 1 утверждён к кодингу.

## Справка: подготовка по правилам APDA
- Motions-раунды: обе команды получают 15 минут после объявления темы.
- Cases-раунды: правительство приносит готовый кейс; оппозиция получает до 15 минут после того, как его услышала.
- Prep есть всегда, длительность настраиваемая (по умолчанию 15).

## Наблюдения по материалам команды
- В доке зачёркивание = «уже сказано», «(why?)» = «докажи», выделение = важное.
- В Excel «стрелки» — это строки (PM → LO, MG → MO). Свои аргументы LO остались в доке.
