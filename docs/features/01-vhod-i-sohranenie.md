# Фича 01: Вход и сохранение

**Статус:** решено для v1 (открыт один вопрос — список имён)
**Обновлено:** 10.11.2026

## Суть
Вход и сохранение максимально элементарные, чтобы не стопорить пользователя.
Безопасность сейчас не в приоритете: личных данных не собираем.

## Решено (пользователь)
**Платформа**
- Только веб, пока под ноутбуки и планшеты.

**Сценарий входа v1 (подтверждён)**
- Экрана входа нет. Первый игрок открывает сайт и сразу попадает в новый флоу — комната создаётся автоматически.
- Вверху плашка «Позови напарника: КОД» + ссылка `/r/КОД` + QR.
- На стартовом экране всегда есть поле «Есть код?»; напарник вводит код и попадает в тот же флоу.
- Повторный заход с того же устройства — **без ввода чего-либо**, насколько это технически возможно:
  открывается последний раунд, на устройстве виден список его раундов; кнопка «Новый раунд» всегда доступна.

**Код**
- Один и тот же код работает **всегда и вечно**.
- v1: у каждой команды свой код и своя запись (комната = одна команда), поэтому защита сторон пока не нужна.

**Синхронизация**
- Правки видны напарнику **сразу** — обязательно.
- **Вдвоём можно писать в одну и ту же ячейку** одновременно (как в Google Docs: два курсора, текст сливается посимвольно).
- Ячейка, где пишет напарник, подсвечена его цветом.

**Имена участников**
- Вместо регистрации — автоматическое саркастичное околополитическое имя + цвет в скобках, например «Ohio Enjoyer (оранжевый)».
- Примеры пользователя: trump, ohio enjoyer, charlie kirk. Финальный список — открытый вопрос (см. ниже).
- У напарников в одной комнате имена и цвета не совпадают.

**Сохранение и аккаунты**
- Комнаты сохраняются **на сервере уже в v1** — обязательно.
- Аккаунтов в v1 нет, но в будущем они будут — архитектура должна это позволить
  (анонимный ID устройства сейчас → позже привязка к аккаунту с переносом раундов).

**Структура данных**
- Сразу «комната → сторона → флоу». В v1 одна сторона; позже к той же структуре добавляются вторая команда и судьи без переделки данных.

## Технические следствия (Claude)
- Автовход: анонимный ID и список раундов в хранилище браузера (localStorage/IndexedDB) + запрос постоянного
  хранилища (`navigator.storage.persist()`). Не сработает в другом браузере, в режиме инкогнито или после очистки
  данных — тогда вход по коду или ссылке. Safari на iPad может стереть данные сайта примерно через 7 дней без
  заходов; PWA на экране «Домой» от этого защищает.
- Совместное редактирование через CRDT (например, Yjs). Текст ячейки — текстовый CRDT (Y.Text), а не строка
  целиком, иначе при одновременном вводе вдвоём один из текстов потеряется.
- Вечные коды: 5 символов без похожих (0/O, 1/I/L) ≈ 28 млн комбинаций; уникальность проверяет сервер.
  Комнату записывать навсегда только после первой правки, чтобы пустые визиты не съедали коды.
- Автосохранение без кнопки: сначала на устройство, потом в фоне на сервер. Экспорт в PDF/картинку.

## Отложено на будущее
- Аккаунты: «Войти через Google» как апгрейд гостя (альтернатива без личных данных — личный ключ из 4 слов).
- Комната на две команды + судья, три разных экрана. Как разделять стороны — решим позже:
  коды команд отличаются последней буквой (например, КОД+G / КОД+O / КОД+J) или «попросить войти»
  (первый на стороне одобряет остальных, как в Google Meet). Замечание: при вечных кодах вариант с последней
  буквой означает, что по своему коду легко угадать код соперника.

## Отклонено
- Логин и пароль: много трения, а для сброса всё равно нужна почта.
- Комната по произвольному слову (как в Jitsi): коллизии вроде «team1», нужна договорённость заранее.

## Открытые вопросы
- Финальный список имён. Claude советует не использовать реальных людей (особенно Charlie Kirk — убит
  в сентябре 2025 г.), а шутить над политикой без конкретных лиц и над дебатными мемами.
  **Для кодинга:** пока взять временный список нейтральных шуточных имён, вынести его в отдельный файл-конфиг.
